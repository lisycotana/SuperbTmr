## 第一部分：项目当前状态

### 1.1 项目是什么

**SuperbTmr** 是一个 **AI Native 的终端平台**，参赛 **AIC 全球校园人工智能算法精英大赛 · 算法创新赛道 · AI+场景创新** 赛题。

仓库：`https://github.com/lisycotana/SuperbTmr`（public，MIT）

一句话定位（已确认，不要改写）：

> SuperbTmr 不是让 Agent 代替人做研究，而是让 Agent 代替人**盯着终端**——它自己登进机器、自己读输出、自己在卡死时读懂报错并判断该重试还是该叫人、自己把结果收回来；人只在下判断的地方出现，而每一次运行的完整过程都留得下来、回得去。

### 1.2 已确认的叙事主线（不要重新选题）

赛道选择经过实际调研，结论已固定：

- **实验/研究闭环场景是空的**：`experiment orchestration terminal` 组合在 GitHub 上 0 命中。
- **AI SRE 赛道是红海**：`ongridio/ongrid`（1078\*，Go 写的，"ops AI Agent that understands your infrastructure, finds the root cause, and fixes it"，含远程执行与告警驱动自动调查）+ `MrGendo/Multi-Agent-AIOps-Platform`（含"人工审批自愈"）+ 一份收录 100+ 工具的 awesome-list。**不要转向这个方向。**

故事主角是 **AI Agent**（干活的人），不是平台，也不是硬件。开场是一个团队的一周，不是架构图。

### 1.6 关键结论（不要重新推导）

1. **整机放置，不做跨机拆分单个作业。** 理由：跨机分布式训练每一步付一次同步税，且作为整体一起失败。这是设计决策，已在计划书 4.3 与风险表中说明理由，不要写成"暂不支持"。
2. **零插桩。** 作业是 JSON 文件，不要求实验代码调用 SDK；指标由正则从终端输出抽取。代价（无法区分"没打印"与"正则不匹配"）已在 6.3.2 说明，不要隐去。
3. **探测与执行是同一套机制。** GPU 清单由长驻会话周期性跑 `nvidia-smi` 产生，不存在第二套执行通道。
4. **卡死检出复用 `notify` 的 silence 事件**，事件驱动而非轮询。代价是"静默"不等于"卡死"，因此判据分层：默认提示，显式声明才判失败。
5. **凭据永不进入 Agent 上下文。** profile 由服务端解析，MCP 读接口只返回名称；写工具默认关闭。

## 第三部分：PPT 写作任务

### 3.1 写作目的

PPT 是**总决赛现场答辩**材料。章程第三十六条：总决赛以参赛团队现场答辩形式举办，团队成员原则上应全部到场，未到场按弃赛处理。

PPT 的读者是**现场评委**，不是阅读者。因此：

- 评委**没有时间**读长段落，每页一个论点；
- 评委**记不住**细节，但**记得住**一个画面和一句话；
- 评委**会追问**，PPT 要经得起"这个怎么证明"。

答辩时间通常 10–15 分钟（含提问），建议 **14–18 页**。
